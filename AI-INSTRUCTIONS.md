# AI Instructions for Pacman Project

You must first analyze the Balloon Shooter project carefully.

Your job is to build the Pacman game using the same coding style, same level of complexity, same file organization, and same logic pattern as the Balloon Shooter game.

Important rules:
1. Do not rewrite the whole project in a new architecture.
2. Do not make the code more advanced than the Balloon Shooter style.
3. Do not edit protected engine files(game.js) unless the requirements clearly allow it.
4. Use separate classes/files for each entity, similar to Balloon Shooter.
5. Entities should be created and connected mainly through index.js.
6. If an entity needs another entity, follow the same searching/accessing style used in Balloon Shooter.
7. Keep naming, comments, syntax style, and structure close to Balloon Shooter.
8. Before coding, inspect the old game and summarize its structure.
9. Then inspect Pacman requirements.
10. Then create a step-by-step implementation plan.
11. Then implement the game.
12. After implementation, test for errors and fix them.
13. Game files like Grid can be changed and enhanced

Protected files:
- game.js should not be edited unless absolutely necessary.

Expected Pacman features:
- Pacman movement
- Maze/walls
- Dots/food
- Score
- Ghosts/enemies
- Collision detection
- Win/lose condition
- Same canvas/game-engine style as Balloon Shooter
